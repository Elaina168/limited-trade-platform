## 资源观察

- JMX 采样 316 条，目标 JVM 累计 CPU 时间约 13.81 秒，采样中堆使用最高约 216 MiB，GC 399 次、累计 659 毫秒。采样间隔 250 毫秒，短尖峰可能落在采样间隙。
- 商品搜索分页在 24 并发时 Hikari 峰值为 10 个连接、10 个等待线程，本人订单分页为 10 个连接、12 个等待线程。缓存列表同期未观测到连接池等待。
- 缓存列表计时窗口内 Redis `SET` 增量为 0，描述的是热缓存稳态。MySQL 有后台扫描等少量查询，阶段前后的 `Com_select` 是实例计数。有限库存批次增量为 11 次行锁等待、累计约 954 ms，累计等待包含多个请求。
- MySQL 摘要的累计耗时靠前语句包含商品关键字搜索的 COUNT 和分页 SELECT，其次还有订单分页及批量订单明细。摘要包含暖机和测量，适合作为补强 5 查执行计划的入口。
- Node 同一时间只有一个基准进程。读取窗口内观测的 CPU 使用约 0.01–0.17 个核等效，事件循环 P99 约 11.7–25.7 ms，包含 10 ms 采样分辨率和本机调度。这轮仅测到 24 并发。

## 如何复跑

1. 按[补强 1](46-strengthening-acceptance-ci.md#从干净检出运行)准备 JDK、Node 和 Java JAR。环境需有 MySQL Server 与配套客户端。
2. 启动独立回环 Redis 和 RabbitMQ，使用空数据目录及单独端口。Redis 可以复用 WSL 内的 Redis 6.0.16。RabbitMQ 使用本机便携版，准备独立 `RABBITMQ_BASE`、节点名、监听端口和分布端口。连接使用回环上的本轮测试节点及其默认访客账户。下面给出本机 Redis 启动示例，在独立终端前台运行。

```powershell
wsl -d Ubuntu-22.04 -- bash -lc 'dir=$(mktemp -d); exec redis-server --bind 127.0.0.1 --port 16379 --dir "$dir" --save "" --appendonly no'
```

RabbitMQ 可按[现有运行脚本](../../scripts/start-rabbitmq.ps1)配置 Erlang 环境。将 `RABBITMQ_BASE` 和 `RABBITMQ_CONFIG_FILE` 指向新目录下的运行配置，设独立 `RABBITMQ_NODENAME` 和 `RABBITMQ_DIST_PORT`。本轮节点名为 `trade_s4_20261123@localhost`，分布端口 25679，配置为 `listeners.tcp.local = 127.0.0.1:5679`，插件文件为 `[].`。直接以前台 `rabbitmq-server.bat` 启动。结束后针对本轮节点停止即可回收资源。

3. 在 `frontend` 指定程序及端口，运行基准。脚本负责启动与回收临时 MySQL、Java 和 JMX 采样进程。

```powershell
$env:ACCEPTANCE_MYSQLD = '<MySQL 安装目录>/bin/mysqld.exe'
$env:ACCEPTANCE_MYSQL = '<MySQL 安装目录>/bin/mysql.exe'
$env:ACCEPTANCE_MYSQL_PORT = '23306'
$env:ACCEPTANCE_JAVA_PORT = '28083'
$env:BENCHMARK_REDIS_PORT = '16379'
$env:BENCHMARK_MQ_PORT = '5679'
npm.cmd run benchmark
```

本地证据在 `tools/trade-benchmark/423e4b348e29/`。包含 `summary.json`、94,860 条 `requests.jsonl` 样本、`jvm.jsonl` 和后端源码差异。逐场景重算样本数、结果分类及百分位，与汇总一致。复用后的默认 Vite 浏览器验收也通过。新的 Redis、RabbitMQ、MySQL 与 Java 验收实例已退出；RabbitMQ 控制命令在等待 Windows PID 时返回错误，前台节点已正常退出，PID 和端口均复核。
