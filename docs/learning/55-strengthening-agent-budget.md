# 补强 10 · Agent 调用、上下文与费用预算

日期：2026-11-23。[实施计划](../superpowers/plans/2026-11-23-strengthening-10-agent-budget.md)

## 准入规则

- 用户确认项目预算为北京时间自然月 100 元。默认每账号每天 50 次已准入提问、同账号 1 个并发，项目总计 4 个并发。一个逻辑提问只记一次，工具循环每次发给模型单独预留和记账。
- 每次模型请求的本地上下文上限默认 32,768 个估算单位，包含输出预留。单位以 UTF-8 序列化字节及协议余量估算，覆盖系统消息、文本、工具定义和参数、工具结果。先裁掉完整的最老历史轮次，保留当轮工具调用和结果。若当轮内容仍超限，返回 413。
- 当前只为 `deepseek-flash` 建立了价格版本，采用公开高峰价的缓存未命中输入 2 元/百万 Token、输出 8 元/百万 Token。使用这个统一上界口径估算，结算不扣除缓存或谷段折扣。模型无价格时拒绝出站。同一模型更换上游供应商时，应重新核对费率。[DeepSeek 官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing)

## 调用链与台账

`TradeAgentService.runTurn()` 调用 `AgentUsageLedger.begin()`。它锁定同一个项目预算行，核对日提问和并发额度，并写入本次提问的租约。每次即将发送时，`Request.reserve()` 检查当月已结算金额、未知用量与在途预留总和，再按配置的整次上下文上限和输出上限预留资金。额度不足返回 429，模型调用尚未发出。

`Call.settle()` 用上游完整的 `usage` 记录真实输入和输出 Token，再按该请求入库时的价目计算微元估算金额。明确在发送前取消的记录释放预留。网络失败、超时、取消后缺 usage 或进程中断导致的不确定调用按未知处理，继续占预留金额，实际 Token 和费用保持空值。下次准入清理已过期的提问租约并标记未知调用。重复结算不会重复计费，付费模型请求不自动重试。

`agent_budget_request` 保存逻辑提问。按月查询 `agent_budget_call` 可以区分预留、已结算、已释放和未知记录，估算 Token 与上游 usage 分列，并保存模型、费率和版本。本地预算限制准入和预留。实际 Token 超过本地估算范围时仍记录上游用量，供应商账单、外部调用和价格调整独立于本台账。

## 验证

- 隔离 MySQL、Java HTTP 模型替身共覆盖 54 项不同专项用例。并发只够一次费用预留时两个账本实例中只有一方成功。重复结算保持一次费用，重启后过期提问释放并发但保留未知预留。工具循环的第一次调用按实结算，第二次超时返回 504，保留未知金额且上游仅收到两次请求。
