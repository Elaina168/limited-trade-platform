# Agent SSE流式输出阶段方案

日期：2026-11-06。状态：用户已确认方案，已实施；103项定向回归与离线打包通过，真实DeepSeek两个连续请求通过。无新增依赖、DDL或开发库变更，详细证据和边界见docs/learning/36-agent-sse.md。

## 目标与现有依据

在已完成的MySQL多轮会话上增加真正的逐段文本输出。DeepSeek以stream模式返回增量，Java将增量通过SSE推送给客户端；不将完整非流式答案人为分片。保留原单轮和多轮JSON接口。本阶段不做聊天页面、不新增数据库表、不新增依赖，不自动提交推送。

当前checkout为codex/bootstrap-boot，基线e4ea5f9。项目Spring Boot3.5.16、Java21、Spring AI1.1.8。实际依赖中的OpenAiChatModel提供stream(Prompt)方法；现有TradeAgentService仅调用call(Prompt)。AgentConversationService使用短事务领取生成资格、事务外调用Agent、核对版本后保存完整轮次。SecurityConfig对未列明端点denyAll，需要显式添加新路由并验证异步响应安全链。

## 实现方式

建议保留Spring MVC，使用SseEmitter输出，由受控异步任务调用框架真实流式API。不切换整个项目到WebFlux。替代方案为在MVC端返回响应式Flux数据流，但生命周期、取消和已存在的同步会话流程需要更多响应式编排，本阶段优先SseEmitter。

复用现有工具白名单、可信ToolContext、JSON参数检查、调用次数上限、请求deadline、实际来源收集以及会话版本和生成令牌。新增流式入口与非流式入口共享必要执行逻辑，避免维护两套权限或工具规则；仅进行支撑本阶段必需的重构。

## 拟新增接口与事件

拟新增POST /api/agent/conversations/{conversationId}/messages/stream，JSON请求继续使用ChatRequest.message，响应Content-Type为text/event-stream。接口保留Session登录及CSRF，客户端未来使用fetch POST读取响应，不用只能发GET的原生EventSource。本阶段通过测试客户端验证，不实现页面。

鉴权、UUID/消息校验、会话归属、过期与并发检查在开始流之前完成；失败保持原HTTP状态且不调用模型。流开始后HTTP状态已确定，后续失败通过error事件表达。

建议事件协议（以下名称为本阶段新定义）：

- start：确认已进入本次流式任务。
- delta：当前模型轮次产生的增量正文，携带轮次标识。属于暂存显示内容，尚未确认完成。
- reset：当前模型轮次最终转为工具调用，丢弃该轮已显示的临时正文，等待工具执行后新一轮回答。
- done：最终完整AgentChatResponse，包含本轮来源、计数和Token信息；只在会话历史提交成功后发送。
- error：受控错误码与简短原因，结束流。部分delta不能被当作成功答案。

每个事件data使用JSON编码，避免换行或特殊字符破坏SSE边界。不向客户端发送工具参数片段、完整订单JSON、地址、密钥或上游原始错误。

## 工具调用与真正流式

每次模型调用使用stream，按锁定框架实际增量格式累计正文、工具调用、完成原因与usage。工具名及JSON参数的增量必须完整汇总后才允许执行；不逐段执行工具。执行前仍做既有白名单、参数和预算检查。

一个模型轮次可能先输出文字，再提出工具调用，因此不承诺每个delta都是最终答案。若该轮转为工具调用，发送reset撤销该轮临时正文，执行工具，将工具请求和结果加入消息历史，再启动下一个模型轮次。最终正常stop且正文非空才构成成功回答，最终文本必须与该最终轮次delta拼接一致。

不为流式额外进行一次模型润色调用，也不让额外调用绕过预算。使用模型实际usage累计Token；供应商流缺少usage时返回null，不推算。模型单次超时与总deadline均覆盖读取流，不允许因持续收到数据而无限延长请求。

## 会话历史、取消与并发

复用完整成功轮次保存：含用户问题、工具调用及配对结果、最终回答，不保存系统消息或未完成半轮。现有六轮/24,000字符裁剪保持。仅收集本轮实际来源，不从历史继承来源数组。

SSE超时、输出失败或客户端断开后，取消上游流订阅并停止后续工具执行，按当前令牌释放生成资格。失败不得持有未结束事务或误释放后来接管者的令牌。后台任务数须有明确上限，超额返回503，不能为每个请求无上限堆积线程或任务；具体容量以实现时现有执行器约定为准并写入说明。

清空、过期或接管后，旧生成不能通过版本/令牌校验提交历史或发送done；已推送的暂存文字不具备成功语义。历史提交是成功的边界：提交之后连接才断开时，服务器可能已保存完整轮次而客户端没有收到done，不能承诺两端原子提交或自动重发。客户端重试不得自动补发原生成任务，本阶段不增加消息幂等或断点续传机制。

网络调用在数据库事务外。对同会话并发继续409，不把长连接与登录Session或数据库锁绑定。

## 代理与安全

核对现有deploy/nginx/server-common.conf：当前代理读取超时30秒。流式路径须关闭缓冲（可通过响应X-Accel-Buffering: no及必要的路径配置），读取超时需覆盖已配置的请求deadline；不为所有接口无条件扩大超时。保持既有转发头及Session/CSRF行为。静态配置检查与真实经过Nginx的流式证据分别报告，不能把文件修改当作已运行验收。
