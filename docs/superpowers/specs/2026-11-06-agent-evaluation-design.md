# Agent轻量评估阶段方案

日期：2026-11-06。状态：用户已确认设计，已实现并完成单次真实评估，自动约束11/12通过；保留1项身份伪造场景的预期过窄问题及追问来源覆盖限制。详见docs/learning/38-agent-evaluation.md。

## 目标与成功标准

用固定业务问题验证当前Java交易助手，并输出可复核的逐项结果，为简历和面试提供有范围说明的真实证据。成功标准是问题集可重复执行，失败不会被遗漏，报告可追溯到问题、实际回答、工具和来源；不以所有模型回答必然通过作为交付条件，不为获得满分反复改题或只保留成功运行。

## 方案选择

采用用户已确认的轻量方案：复用JUnit、Jackson、现有测试库夹具及Agent服务，新增固定问题集和评估入口。不增加生产接口、数据库表、第三方依赖或服务。完整评估后台、模型裁判和历史对比平台工作量较大，当前不采用。

现有RuleRetrievalEvaluationTest负责检索层的固定校准/评估集；AgentDeepSeekLiveTest、AgentRagDeepSeekLiveTest、AgentConversationDeepSeekLiveTest及AgentSseDeepSeekLiveTest已有少量真实联调。现有协议、权限、并发、预算、超时、断流等确定性测试继续复用，不能将这些检查算成真实模型问题通过数。

## 问题与判定

拟定12个固定场景，覆盖本人订单列表、本人订单详情、空结果、他人订单、支付截止规则、取消规则、超时库存回补、无资料政策、拒绝取消订单、伪造身份指令、多轮追问重新查询及清空后的上下文隔离。多轮场景含多次请求，报告分别统计场景数和请求数；具体自然语言及预期写入版本管理内的问题集，实现时固定。

自动判定只针对可检查的约束：应调用的工具、允许的工具范围、实际来源文档、固定订单事实、预期错误状态、清空后不可沿用的订单信息、写请求前后订单状态保持一致。依据当前实际工具名和返回字段实现，不要求固定措辞或精确匹配整段答案。关键结论的关键词仅标为规则检查，不称为语义准确率。

人工复核单独记录事实是否正确、解释是否有来源支持、是否编造执行结果及是否误导用户。自动报告默认标记人工复核待完成，不自动给出主观正确性结论；本阶段执行后复核实际回答，并保留判断理由。

## 执行和报告

新增评估默认关闭，必须显式开启才访问DeepSeek；沿用本机已有密钥，不读取到输出，不改变config/agent.properties中的开关。只使用test profile及测试库，沿用现有固定夹具和事务/清理机制，不修改开发库。执行前检查测试库固定账号和订单是否存在，存在冲突则停止，不清理未知数据。

每次运行生成独立报告，记录运行时间、模型标识、场景编号、问题、预期约束、实际回答、toolsUsed、knowledgeSources、modelCalls、toolCalls、totalTokens、durationMs和各项检查。无响应时记录已知错误及实际耗时，未知Token不记为0。只处理预期模型/业务异常以记录失败，意外异常仍应使运行失败；不静默忽略、不自动重试。

断言失败也必须保存本次已经产生的结果，未执行场景明确标注；报告记录整次运行是否完整。汇总自动约束通过数、失败数、实际请求数、可获取的Token合计及成功响应耗时；耗时只作为当前环境小样本观察，不给出吞吐量、并发性能或总体准确率结论。

原始回答和完整来源保存在被忽略的tools目录，版本管理仅保留问题集、评估代码、运行说明及脱敏结果摘要。无需引入通用评估框架或额外抽象。

## 验证与边界

先离线验证问题集、判定和报告行为，确认失败也留证据；再显式运行一次有限规模的真实DeepSeek评估，保留全部结果，不因未通过而自动反复调用。复用必要的Agent关联回归；如发现与本阶段相关的明确缺陷，最小修复后定向验证并保留前后结果，否则报告限制，不扩展业务功能。

更新阶段学习说明及必要的路线记录，分清确定性测试、真实模型评估、人工复核三种证据。完成后停止，不安装Docker、不做部署、不自动提交或推送。当前SSE和聊天页面的未提交改动全部保留。
