# 当前交易项目补强阶段计划

> **For agentic workers:** 实施时使用superpowers:executing-plans逐阶段执行；本文是总体路线，不是一次执行全部阶段的授权。每阶段开工前读取真实代码、完成该阶段设计和具体实施计划，不按过时的行号或猜测的接口修改。不自动提交推送。

**Goal:** 将已有Java交易与Vue/Agent业务增强为可复现交付、有正确性与性能证据、有预算和安全约束的全栈项目。

**Architecture:** 保留交易单体、Session/CSRF和既有消息可靠性链路。先在本机建立可移植验收和性能基线，再逐项优化，最终验证容器部署；Agent产品、安全、预算和检索增强独立验收。

**Tech Stack:** 现有Java/Spring Boot/MyBatis/MySQL/Redis/RabbitMQ/Spring AI/DeepSeek/Vue/TypeScript；新增组件在对应阶段盘点兼容性与资源后确定版本。

**Spec:** ../../plans/2026-11-23-strengthening-scope.md

## 全局约束

- 阶段完成情况以学习记录与验证证据为准。
- 按补强1—15编号，避免与已完成Vue1—7阶段混淆。
- 这是多子系统路线；每阶段形成独立可验收的实施计划、学习记录与结果，不一次性修改全部子系统。
- 采用范围文档的全部共同约束。所有阶段必须保留购买幂等、金额/库存约束、账号归属与CSRF语义。
- 日常验证只覆盖改动及必要关联；总体性能、真实中间件、真实模型分别记录，不混报。
- 任何依赖升级、迁移、缓存/消息协议变化均在对应阶段列出，不以本计划代替版本核对。

## 第一批：复现、交付与基线

### 补强1：可移植自动验收与CI基础

- [ ] 提取关键浏览器流程，移除个人绝对路径，环境/端口/浏览器可配置；说明依赖安装与清理办法。
- [ ] 分类确定性检查、真实中间件集成、真实模型三类入口；CI默认不调用付费模型。
- [ ] 使用隔离账号/数据库资源和可重复夹具；失败也能定位自有资源并清理。
- [ ] 加入前后端构建、类型检查及阶段选定回归；CI状态与提交SHA关联。

验收：干净检出按文档可运行；CI实际成功一次，并验证故意失败能阻断；凭据不进入源码/日志；正常与失败清理都验证。Docker服务化集成任务可在补强3补齐，不以此阻塞离线CI。

### 补强2：Vue正式静态托管与统一入口

- [ ] 静态服务直接提供dist，配置SPA回退、静态资源缓存、同源/api代理及SSE关闭缓冲。
- [ ] 与旧Java原生入口明确区分，保留原有调试路径。
- [ ] 验证深链接刷新、登录/退出、CSRF、管理权限、流式及停止。

验收：不依赖Vite dev/preview即可完成买家、管理与Agent页面基本路径；API错误不能被错误替换为index.html；敏感/个人响应不进入公共缓存。HTTPS在实际部署环境确定后补验。

### 补强4：并发正确性、吞吐和延迟基线

- [ ] 固定提交、机器资源、数据规模、数据库设置、负载模型、预热、持续时间与重复次数。
- [ ] 覆盖有限库存竞争、同键重试、支付/取消/关闭竞争、商品读取、分页查询。
- [ ] 区分成功成交、库存不足、429、系统错误；分别报告发送速率、完成吞吐、P50/P95/P99。
- [ ] 记录CPU、内存/GC、连接池、SQL/锁等待、缓存回源及MQ积压；压测端能力也需核对。
- [ ] 验后对账订单/库存/活动名额/券/幂等和Outbox，不把HTTP200作为唯一正确性依据。

验收：脚本、原始样本、环境说明和对账可复现；不预填QPS目标；记录到瓶颈即可，不以无限加压损伤共享环境。Agent首字/总时长/费用另测，不混入交易吞吐。

## 第二批：有对比证据的交易优化

### 补强5：MySQL调优案例

- [ ] 选择基线中真实存在的查询问题，构造有代表性且可清理的数据分布。
- [ ] 保存EXPLAIN/必要时EXPLAIN ANALYZE及原SQL/索引，再做最小调整。
- [ ] 比较相同数据与负载下扫描、耗时、结果一致性和写入/存储成本。

验收：形成至少一个可复现前后对比；如果原查询不存在明显瓶颈，不编造改善数字；大偏移分页与索引实验不擅自改变现有分页协议。

### 补强6：缓存基础升级

- [ ] 根据/api/products与/api/products/search的实际使用选择热点键，不缓存任意搜索组合导致无限增长。
- [ ] 加热点回源合并、TTL抖动、按不存在ID的负缓存；区分空列表与不存在资源。
- [ ] 对允许短暂旧值的展示数据实现逻辑过期和受限后台刷新；硬失效/删除的数据不得继续返回。
- [ ] 定义冷热未命中、首载失败、刷新失败、等待与拒绝行为，监测回源次数。

验收：热点并发显著减少重复加载；负缓存能正确失效；抖动分布和刷新资源有界；失败可见；库存/支付判断不依赖展示缓存。单JVM与多实例的保证分别说明。

### 补强7：Caffeine、布隆过滤器与缓存一致性/故障治理

- [ ] 对合适的热点数据接入Caffeine，明确容量、期限、多实例失效与失效消息丢失语义。
- [ ] 实现可验证的布隆过滤器场景：假阳性仍查询、索引更新/重建、启动未就绪与新数据不能误拒绝；不对任意搜索词建过滤器。
- [ ] Redis故障时限制回源并发/速率；展示旧值、拒绝和允许回源的条件由数据契约决定。
- [ ] 用可控时序复现旧值回填，再选择版本/失效栅栏等方案；覆盖失效操作失败，不承诺MySQL与Redis强一致。

验收：多实例、并发更新、热点到期、Redis不可用、恢复后的数据均有测试；新商品不被永久漏掉；不FLUSHDB；与补强4/6对比并披露剩余陈旧窗口。组件纳入实现/对比，不意味着所有接口默认启用。

### 补强8：交易入口令牌桶

- [ ] Redis Lua原子维护补充与扣减，明确容量、速率、时间来源和重试语义。
- [ ] 保留固定窗口对比模式，校验突发、持续流量、多个Java实例共享预算。
- [ ] 保留429/Retry-After及限流依赖故障保护，核对幂等重试是否消耗预算。

验收：容量/补充边界可重复验证；实际速率曲线符合定义；不因客户端伪造身份获得额度；性能不能以取消库存正确性保护换取。

## 第三批：Agent产品、安全与成本

### 补强9：会话列表与历史读取

- [ ] 先确定24小时过期、10会话上限、删除/清空含义以及可见记录保留策略。
- [ ] 分离用户可见消息和发给模型的上下文，不能直接把工具内部消息展示给前端。
- [ ] 增加本人会话分页/选择/历史读取及Vue恢复；迁移方案保护已有数据，缺失旧历史不得伪造。

验收：刷新/重登可按保留策略读取本人记录；他人列表与详情不可访问；裁剪模型上下文不意外删除承诺保留的展示历史；生成中读取/清空行为明确。

### 补强10：调用额度、Token与模型费用预算

- [ ] 区分用户逻辑提问次数、实际模型请求次数、Token、并发和费用；确定周期与限额，金额由用户在实施前选择。
- [ ] 系统提示、工具定义、历史、工具结果、输出预留共同参与上下文预算；完整保留工具调用/结果配对。
- [ ] 持久化原子预留、实际结算、释放与未知用量状态；版本化模型价格，未知不计零，不自动重试付费请求。
- [ ] Token预估与上游usage分开，重启和并发不得重复记账；没有可靠Token算法时如实标为估算。

验收：并发不能超用自建额度；拒绝发生于模型调用之前；中断/超时/工具循环和进程恢复可对账；本地预算与供应商实际账单的保证边界明确。不做对用户真实收费的平台。

### 补强11：细粒度工具权限与攻击样本

- [ ] 基于现有认证主体、角色、资源归属及工具动作做服务端授权，不相信模型传来的用户ID。
- [ ] 受限审计记录调用与拒绝，不记录密码/令牌和不必要的私密正文。
- [ ] 建立版本化攻击集：身份伪造、工具越权、资料/工具注入、上下文污染、信息泄露、长输入/长工具返回。

验收：直接调用和模型调用均受控；权限与额度绕过被确定性测试阻断；模型安全拒绝与后端授权分别评价；仍不暴露交易写工具。

## 第四批：AI评测与当前RAG增强

### 补强12：持续评测与多配置基线

- [ ] 复核已有20条检索集、12场景Agent集及历史失败；保留旧版，重新跑完整的新版本而不是拼接定向结果。

### 补强13：关键词＋向量混合检索与RRF

- [ ] 围绕真实规则补精确术语、歧义、无答案等检索场景；订单事实仍走实时工具。
- [ ] 增加中文关键词召回，与现有BGE向量召回并行/独立执行，明确候选、去重与来源元数据。
- [ ] 使用RRF融合排名，保留单路对照，不相加不兼容的原始分数。

验收：同一留出集比较单路/混合方案效果及耗时，来源真实可追踪；权限和拒答不回退；如果质量没改善，如实记录并调整而非宣称必然提升。

### 补强14：Rerank、按需改写与向量库决策

- [ ] 对失败样本试验Rerank，对多轮指代/歧义试验Query Rewrite，防止改写增加虚假条件。
- [ ] 比较收益、错误、额外模型/推理耗时和成本，决定默认启用与适用路由，不机械加入所有请求。
- [ ] 根据数据规模、过滤、共享索引和部署需求评估pgvector/Milvus；优先评估pgvector，但只有单独设计获确认后才安装/迁移，不默认双库同时用。

验收：提供可开关的实验与清晰取舍；若迁移，另验中文检索、向量维度/版本、索引重建、来源/权限一致、备份恢复。向量库迁移本身不等于召回提升。
