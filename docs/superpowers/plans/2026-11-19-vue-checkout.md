# Vue前端第三阶段实施计划

沿用已授权的七阶段计划，第三阶段实现购物车、收货地址、优惠券选择和结算。基于现有Vue3/TS和Java接口，不增加依赖或变更后端协议。阶段二尚未提交的文件保留，不自动提交或推送。

## 接口约束与实现选择

- PUT购物车数量表示最终数量，成功204。商品选购页让用户输入目标数量并保存到购物车，购物车支持改量、移除、勾选最多50种商品。
- 地址支持创建、修改、删除、设默认；姓名/省市区最多50字符，详情200，手机号1[3-9][0-9]{9}。默认地址用于预选；无地址时引导地址管理。
- 购物车checkout只接受productIds、addressId、requestId；活动券仅用于单商品POST /api/orders。新增受保护的选购页支持普通购买、活动购买和选择本人可用活动券。
- 待确认购买按用户ID保存至sessionStorage，首次提交前持久化requestId及参数。未知结果、刷新和重试复用原请求；未知结果期间不允许修改购买意图或购物车。重试不自动循环，明确4xx按当前后端幂等查询顺序处理。
- 成功后进入受保护的订单创建结果页，通过GET /api/orders/{id}读取成交金额、商品与地址快照。支付、取消、订单列表留第四阶段。

## 实施顺序

1. 增加并验证PUT/DELETE与204支持、业务类型及API函数。
2. 实现可测试的购买意图状态，验证未知结果重试、刷新恢复、账号隔离、CSRF拒绝和旧响应。
3. 实现地址页、选购页、购物车与结果页；公共布局显示待确认购买与原参数重试入口。
4. 增加导航、商品选购与活动购买入口；账号变化清理组件数据与表单。
5. 类型检查、构建、真实隔离测试库Chrome联调（落库、快照、幂等、库存/券冲突、权限与移动端），清理本次数据及实例。
6. 完成源码复核和学习记录。讲解按用户偏好覆盖TS/JS与主要变量，带文件和行号，模板与CSS仅概括，SQL和测试不讲。

## 成功标准

普通购买、活动券购买、购物车多商品结算能真实落库；地址和购物车只能操作本人数据；金额以服务端返回为准；丢失成功响应后相同requestId只生成一张订单；账号切换不展示或提交旧用户数据；手机布局可用，测试与构建通过。
