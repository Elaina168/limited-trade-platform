# Vue第五阶段：管理员业务页面

按已授权的七阶段计划，接入现有分类、商品、活动、券和订单发货接口。保留阶段二至四未提交改动；不增加依赖、不扩展后端协议、不自动提交推送。

## 真实接口与范围

分类POST创建/PUT重命名，公共GET读取；商品管理GET全部、POST创建OFF_SALE（初始库存非负Integer）、PUT仅名称/价格/分类、PATCH状态。价格最多8位整数2位小数且大于0。

活动管理只有POST创建，绑定已有商品、正整数名额、开始早于结束。列表使用已有GET /api/activities。券只有POST创建，金额和时间遵循CouponService：优惠小于门槛；领取/使用区间各自递增；领取结束不晚于使用结束；使用范围不超出活动。券列表使用GET /api/activities/{id}/coupons。

管理订单GET分页可按status/userId，列表AdminOrderResponse含userId但不含地址；管理详情GET返回OrderResponse含地址但无userId。发货POST只允许PAID且有地址，重复同物流幂等，冲突409。保留物流只读展示，管理员发货后买家可以在第四阶段确认收货。

## 实施与验收

1. 类型/管理API与PATCH支持；表单金额、整数和券时间验证，先观察检查失败再实现。
2. 六个管理业务页：分类、商品、活动、券、订单列表、订单详情发货。共享管理页读取/提交状态，身份或角色变化清空私有数据和草稿。未知写结果先刷新核对，不自动重发；保留同账号焦点刷新期间草稿。
3. 所有路由要求requiresAuth和requiresAdmin，管理首页及导航连接新页面。原USER与本人订单页面保持现有边界。
4. 前端检查、类型检查与构建，隔离测试库真实Chrome验证分类重名、商品上/下架及修改、活动与券创建/使用、管理员订单筛选/发货与买家收货、403与未知结果、身份变化和移动端；复核并清理测试样本和临时实例。
5. 学习记录覆盖所有新增/修改运行代码，带文件路径和行号，重点TS/JS；HTML/CSS概括，SQL/测试不讲。完成后停在第五阶段，不自动进入Agent页面。
