# 补强 6 · 商品缓存基础

**目标**：减少在售列表并发回源，提供有界的商品 ID 负缓存，同时维持交易读写以 MySQL 为准。

**设计**：列表继续以原 JSON 数组原子写入 Redis。用一次读取同时获得值和 TTL。硬 TTL 随机 25–30 秒，最后 10 秒内返回当前值并合并一次异步刷新。每 JVM 同时至多一个列表加载，冷读等待最多 2 秒。事务提交后删除列表并更新本机版本，旧任务仅在版本匹配时能写入和返回。刷新失败保留 Redis 原 TTL，1 秒后允许再试。

1. 给真实 Redis/MySQL 集成测试添加冷启动竞争、软过期、提交失效、抖动、失败和不存在 ID 的断言。先运行能体现缺失行为的用例。
2. 新增公开在售商品按 ID 读取，Vue 选购页使用该入口。只为数据库确实不存在的 ID 写 5 秒负缓存，256 个固定槽保存确切 ID。上架事务提交时清除对应槽。保持搜索走数据库，库存、金额及权限由既有交易入口判断。
3. 核对现有缓存序列化和提交/回滚测试，运行隔离 Redis/MySQL 及 Vue 浏览器正常交易。记录负缓存边界、回源计数和单 JVM 保证。跨 JVM 防旧值回填及 Redis 故障策略留到补强 7。
