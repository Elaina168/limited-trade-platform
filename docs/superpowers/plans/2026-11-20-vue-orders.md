# Vue第四阶段：本人订单管理

沿用已授权的七阶段计划，交付本人订单分页与状态筛选、完整详情、模拟支付、取消、确认收货。保留阶段二/三未提交内容，不自动提交推送，不增加依赖，不改Java/SQL协议。

## 已核对的规则

GET /api/orders支持page、size、status，分页含page/size/total/items。状态为PENDING_PAYMENT、PAID、CANCELED、CLOSED、SHIPPED、COMPLETED。GET /api/orders/{id}只读取本人订单，其他用户或不存在均404。

POST /api/orders/{id}/pay：待支付且未过期；已支付重复请求返回原结果。cancel：待支付可取消并返库存/释放券，已取消重复返回原结果；过期但尚未关闭的待支付订单仍可取消。receive：已发货转完成，已完成重复返回原结果。页面只开放当前允许操作，实际条件由后端执行。

## 实施任务与完成标准

1. 扩展订单状态/分页类型、接口函数与状态动作策略；先验证筛选参数、CSRF、截止边界。
2. 购买store增加已查到订单的确认方法，仅匹配当前账号pending.requestId时清理，不因为空页或无关订单清理。
3. 实现受保护/orders和/orders/:id，保留旧/checkout/result/:id兼容入口，共用完整详情。成功下单与待确认重试转到新详情页，增加订单导航。
4. 详情显示成交商品、金额、地址、券、物流和时间；支付注明模拟，取消/确认收货前确认，提交期间互斥。写操作失败/结果未知后先GET刷新确认，不自动重发。保护账号切换、路由重用和旧响应。
5. 单元检查、类型检查和构建；真实隔离测试库Chrome验证分页筛选、支付/取消库存券状态、收货与幂等、截止/冲突、权限、未知结果和移动端；复核并清理测试数据与临时实例。
6. 学习记录覆盖全部运行文件、TS/JS主要变量与调用流程，讲解带文件和行号，HTML/CSS仅概括，SQL和测试不讲。

成功标准：USER只能查询和操作本人订单，按状态显示可用操作；未知结果可读后确认且不重复购买；新旧详情入口可用；验证通过后停止本阶段。
