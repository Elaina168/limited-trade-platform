# 补强 4 · 交易并发正确性、吞吐与延迟基线

**目标**：采集优化前可复跑的原生单机基线，同时确认竞争请求后的交易状态。

**环境**：复用已有 Node 24、JDK 21、MySQL、Redis 和 RabbitMQ。用补强 1 的临时 MySQL/JVM 启动流程，Redis、RabbitMQ 另用独立实例，直连 JVM 回环 HTTP。保留真实缓存、限流、定时任务及 Outbox，关闭 Agent。

1. 构造 1,000 件可售商品、12 名买家及单独管理员。用独立的存量、活动和券测试不同买家抢购；并发同键重试与 429 验证单独执行。分别验证支付/取消与过期后支付/取消/扫描关闭，并核对库存、名额、券状态和 Outbox。
2. 读取使用闭环并发 1/8/24，暖机 1 秒、采样 3 秒、重复两次。比较缓存列表、关键字商品分页和本人订单分页。写入使用固定批次数，区分提交、库存不足、限流和系统错误。
3. 记录逐请求时间、发送/完成速率及最近秩 P50/P95/P99；用 JDK JMX 采样 JVM CPU、堆、GC、Hikari，用隔离 MySQL 和 Redis 计数器、RabbitMQ 管理快照及 Node 指标记录上下游。证据保留在运行目录外。
4. 执行基线，核对样本数量、对账结果、临时资源回收。保留环境与原始数据位置，后续性能优化复用本入口和参数。部署环境与 Agent 评估单独记录。
