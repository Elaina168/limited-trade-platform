# 补强 5 · MySQL 本人订单深分页

**目标**：对补强 4 中的本人订单分页做可复现的调优。保留总数、页码、大小、状态筛选、归属、详情和降序。

**设计**：复用独占 MySQL/JVM 验收启动流程。构造两名买家的 15 万笔交错历史订单。对无状态过滤的原查询和延迟关联候选，在同一数据上交错执行，保存执行计划、每次服务端耗时和扫描行数。结果逐页按完整投影对比。

1. 先测现有生产 SQL 与候选 SQL，覆盖浅页、中间页、深页和越界页，比较现有索引覆盖程度与回表成本。
2. 根据实测决定是否对无状态过滤的深页采用候选方案。复用既有索引，保持 COUNT、状态过滤和分页协议。
3. 启动修改后的应用，核对 HTTP 响应及真实数据库执行的 SQL，检查边界、归属过滤及详情。保存复跑入口和证据，记录写入和存储成本边界。
