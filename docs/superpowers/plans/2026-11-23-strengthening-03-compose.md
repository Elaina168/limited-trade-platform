# 补强 3 · Docker Compose 真实部署

**目标**：用独立的 Compose 项目重现 Vue、Java、MySQL、Redis 和 RabbitMQ 的完整部署。

**设计**：以本机已构建的 JAR 和 dist 为镜像输入。容器 Nginx 复用补强 2 的页面、缓存和 API 规则，用 Compose 服务名代理到 Java。容器私网、随机凭据和命名卷按项目隔离。镜像上下文采用白名单。手动集成 CI 使用和本机相同的验证脚本。

**安装边界**：Windows 无 Docker，Ubuntu-22.04 是 WSL2，启用了 systemd。安装前请用户确认 Ubuntu 仓库的软件包与镜像下载方案。

## 实施与验收

1. 拆出 Nginx 共用 HTTP 和站点规则，新增容器入口及独立白名单。保留 Windows 静态入口。
2. 扩展 Compose、命名隔离凭据、端口与健康检查。保留默认部署的外置凭据，已有 MySQL 卷按迁移方式处理。
3. 验收脚本仅对全新命名项目执行五服务启动、Vue/API 探针、注册登录下单、Redis 缓存、MQ 投递确认、应用停止重启、强制重建、Redis 故障与恢复。检查订单与库存，输出限定范围的日志，退出时 down 保留卷。
4. 在有授权和运行时的环境按文档真实执行。区分配置校验、容器健康、业务及故障演练的证据。GitHub 托管工作流由授权推送后触发。
