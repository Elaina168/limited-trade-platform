# 补强 7 · 多级缓存与故障治理

1. 在真实隔离 Redis 上复现两个实例间的旧列表回填。共享随机版本通过 Lua 原子读取、失效和比较写入，保持列表的原 JSON。Redis 恢复时重试未完成的失效。
2. Caffeine 只缓存单个商品列表，默认 1 秒，本机提交立即失效，其他实例到期重读 Redis。根据本地显示数据选择是否使用有界布隆索引。只将命中用于可选的直查提示，漏判、假阳性和冷启动均按正常查询处理。
3. Redis 连接和命令超时触发本机限额，列表合并仍保留。列表及详情共用最多 1 个数据库降级任务、每 250ms 至多一次；已提交业务的失效失败写日志并重试。
4. 验证旧回填、额度、恢复、布隆误判、启停及既有交易。在原生隔离环境运行相关测试，记录单机和多实例边界。
