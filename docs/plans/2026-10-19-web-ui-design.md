# 第二十一阶段：现有业务完整前端

## 范围

用户要求一次完成当前后端能力对应的前端：注册/登录/退出、商品分类搜索分页、普通立即购买、活动浏览领券与购买、购物车选中结算、地址CRUD/默认、本人券、订单列表详情/支付取消收货，以及管理员分类/商品创建修改上下架、活动和券创建、订单筛选详情发货。

原生HTML/CSS/ES modules放Spring Boot static目录，同源Session/CSRF，无新增依赖、外部CDN或托管。界面采用浅色商店布局、深蓝操作色、商品卡片、桌面导航与移动端折行、表单弹窗；所有动态业务文字用textContent。仅页面所需路径开放GET，不放开API权限。

## 必要后端补充

活动现只有按id查询，商品管理缺含下架商品的列表。仅补GET /api/activities和GET /api/admin/products两个只读数组入口，复用Activity、Product和权限，不增加交易规则、迁移或写入口。其他字段及HTTP方法以源码为准。

## 关键交互

- 每次写入前取当前CSRF，登录使用表单编码，注册及业务写入使用JSON；不自动重试写请求。身份只取/api/auth/me，密码和令牌不入Web Storage。
- 下单用crypto.getRandomValues生成16随机字节的32位十六进制requestId，普通HTTP下也可使用。网络/5xx结果不确定时按用户保存当前购买意图及原requestId到sessionStorage，提供原请求重试和查订单，不生成另一笔重复购买；参数改变不会复用旧key。成功后清除；已知4xx拒绝后允许修正重试。
- 导航只显示当前角色的入口，401清理私有视图，403/409/429/503和网络异常明确提示。异步页面加载使用版本检查避免旧响应覆盖新页面；会话变化时关闭私有弹窗。
- 立即购买/结算UI要求选地址，沿用后端对历史无地址订单的限制。活动不进入购物车，购物车无券；优惠和库存以服务器返回为准。仅状态允许时提供订单动作。
- 管理商品修改不提供库存编辑（后端无对应接口），新商品初始OFF_SALE；活动/券只创建。无退款、删除商品、活动修改或真实物流操作的假按钮。

## 验证

遵从用户最新要求：只做本次必要最小测试，不全量回归；为更新可运行JAR执行跳过测试的打包。用一个MockMvc专项检查静态资源开放、两个读入口和权限，并复用真实数据库快速跑注册/登录/购物车结算/活动用券/履约核心链路。浏览器使用已存在的Playwright/Chromium，拦截请求提供契约夹具，检查所有页面操作、表单方法/字段、CSRF轮换、错误/幂等重试、XSS文字及移动布局；不启动此前被拒绝的临时Java HTTP探针，不将浏览器夹具称为真实HTTP后端部署。一次独立只读复核，必要修复只跑关联用例。
