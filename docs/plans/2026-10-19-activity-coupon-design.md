# 第十八阶段：活动专用满减券

## 已确认范围与成功标准

优惠券绑定一个现有限时限量活动，仅原单商品活动下单入口可选一张本人已领取的券。领取时间和使用时间独立，均为左闭右开；统一截止时间，不采用领取后滚动有效期。领券不扣商品库存或活动销售名额。下单、占券、金额及规则快照、Outbox同事务；支付核销，取消/超时释放。有效期内下单后券过期不改变订单应付金额，订单仍受15分钟支付期限约束。

本阶段最小实现选择：每人每种券限领一张，重复领取返回原券；券总量独立于销售名额，领取后不返还发放额度。优惠为满额减固定金额，门槛和减额均为正且减额严格小于门槛，保证正应付。使用区间必须包含在活动区间内，领取截止不晚于使用截止。管理员只能创建，暂不增加修改、作废、叠加、自动选券、购物车优惠或原单商品地址。

## 数据与接口

- `activity_coupon`：活动、名称、门槛/减额、发放总量/余量、四个时间字段，规则创建后不可修改。
- `user_coupon`：本人领取记录，唯一 `(coupon_id,user_id)`；AVAILABLE → RESERVED → USED；取消/关闭 RESERVED → AVAILABLE，清除当前 order_id。过期由时间判断，不批量更新状态。
- `order_coupon`：订单主键，一份不可变优惠快照，记录 user_coupon_id、coupon_id、activity_id、名称、门槛、减额和使用区间。取消后的旧订单继续保留快照，同张用户券可用于后续订单。
- `trade_order.discount_amount` 默认0；`original_amount` 为 `total_amount+discount_amount` 的持久化生成列。旧单原金额等于应付；现有总金额字段继续表示应付。原明细仍保存未优惠金额。
- POST `/api/admin/coupons` 创建；GET `/api/activities/{activityId}/coupons` 查活动券；POST `/api/coupons/{id}/claim` 领取；GET `/api/coupons/mine` 查本人领券记录及券规则、过期标记。
- 原 CreateOrderRequest 新增可空正数 `userCouponId`；旧Java四参构造保留；幂等比较包括该编号。购物车保持原接口。
- 用户和管理员订单响应均增加 originalAmount、discountAmount、coupon 快照。

## 事务和锁

领取：用户锁 → 查既有领取 → 券模板行锁 → 等待后取时间 → 条件扣发放额度 → 插入用户券。
创建：用户锁 → 幂等 → 活动锁 → 商品锁 → 用户券锁 → 等待后取时间 → 校验使用时间、归属、活动、状态和门槛 → 扣活动名额、写订单/快照并占券。模板只读不加锁。
取消/超时：订单锁 → 活动 → 商品 → 用户券；支付：订单 → 用户券。占用、核销和释放仅更新当前订单对应记录，无反向获取订单锁。创建不锁旧订单。读取模板不加锁且不提供修改入口，避免模板锁与用户券锁形成循环。
